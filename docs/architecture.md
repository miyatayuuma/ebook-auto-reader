# アーキテクチャ

単一のKotlinアプリ内で責務を分ける。P2ではOCR、読み推定、TTSの実装を試験用の入力・出力と交換できる、小さな境界を設ける。

| 責務 | 出力・契約 |
| --- | --- |
| DMMの画面取得・移動 | 対象ウィンドウ確認、取得可否、遷移方向と前後の確認結果 |
| OCR・レイアウト | 原文、矩形、読み順候補、分類の根拠、欠損情報 |
| 読み推定 | 原文の範囲に対する仮名、出典、確信度 |
| 特殊ページ | 本文・図表・章扉・白紙・認識不能。確認できた情報から再生または停止 |
| ページ連結 | 文を構成する原文範囲の列。ページをまたいでも出典を保持 |
| 先読み・音声 | 再生可能な残時間で先読みを制御。文の音声と原文範囲、再生進捗、失敗 |
| 同期・操作 | 音声位置、表示確認済みページ、セッション世代、手動操作と停止 |
| 記録・メモ | 最後に確認できた位置、統計、メモ、必要最小限の引用 |

## 原文と発音

原文と読みは別に保持する。検証できた組版ルビ、本人の書籍別辞書、条件が一致する共通辞書、文脈と形態素解析、TTS既定の順を初期方針とする。曖昧な上書きは避ける。音声入力だけを組み立て、音声側の範囲を原文へ逆引き可能にする。本文の生成による書き換えを行わない。

## 先読みと同期

- `表示確認済みページ`、`OCR済みページ`、`現在再生中の原文範囲`、`再生完了済み位置`を個別に管理する。一時的な表示先行は通常再生時だけ許容する。
- 文末未確定の原文は保持し、次の確認済みページの先頭とつなぐ。前後に別々の段落だという根拠がある場合に境界を立てる。章扉等を本文へ混ぜず、間に確認済みの図表ページがある場合は本文の文と通知音・注釈の順序を別管理する。未知のページに到達したら保留する。
- 移動と検証は1件ずつ。画面安定後に本文領域の画像署名、レイアウト、取得できる進捗表示、移動方向を照合する。OCR文字列の一致だけで重複としない。同文・同レイアウト・ページ再配置を想定する。無変化や不確実な遷移では停止する。巻末は別の根拠を要する。
- 再生前の合成と、実再生で進んだ位置を区別する。ページ取得・認識を合成・再生と並行し、最大4ページ先、最大8音声で合成済み音声をキューに積み、再生ヘッドのタイムラインを原文範囲へ対応付ける。途中位置が不明なら文頭を確定済み再開点とする。
- 中断・手動操作では先読みと次の自動操作を止め、世代を更新して古い応答を無視する。表示復元は記録済みの逆移動を上限に、一歩ずつ署名照合する。手動移動や照合失敗を検知したら自動復元を終了し、確認を求める。OSがプロセスを強制終了した場合は、次回起動時に確認する。
