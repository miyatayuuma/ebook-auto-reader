# P2.7 role split — user decision 2026-11-28

Status: approved product direction, implementation not yet authorized by this decision alone. Supersedes the P2.6 capture-first Android roadmap previously recorded in this file (prior revision retained in Git history). This PR is a decision record, not yet the normative integration of product-spec/AGENTS.md.

## Android: minimum-optimal TalkBack page-turn companion
- Objective: fill the missing automatic page-turn function of TalkBack in DMM Books. TalkBack owns speech; no independent TTS, sentence assembly, permanent page-text storage, page-number/title OCR, book DB, or speculative prefetch in the lightweight runtime. Arbitrary font size and margins including minimum; no required numbered/title layout.
- Explicit user-enabled start/stop, TalkBack state checks, notification/Quick Settings; one turn controller, no overlay/touch interception. Stop or hold on menu, shade, other app, lock, uncertain identity/transition; no action after stop. Keep screen awake during active reading and optionally minimum brightness with restoration of prior values. Do not assume screen-off reading.
- Reuse proven silence-based page-end approach (user reports past success). Recover prior implementation and validate supported audio-state signal, initial speech confirmation, pause/debounce/timeout behavior, accessibility gesture coexistence, manual page change and final-page handling. Silence alone does not prove page completion; no continuous blind turning. Verify stable changed frame and expected navigation evidence; no repeated blind turns.
- Figure-only pages may be skipped. Use minimal positive evidence only when speech does not start; consider detector-only DEIM as fallback, without text recognition, and prefer lighter reliable alternatives if measured. Mixed text/figure or unknown silent pages must not be silently skipped. No requirement to read page numbers.
- P2.7A: restore proven TalkBack turn loop and on-device signal probe; P2.7B: conditional figure-only detection and display/power controls; P2.7C: lightweight build and long-run acceptance. Measure reliable manual/auto turn, zero accidental skips in representative tests, stop behavior, CPU/memory/battery, and minimum-size layout. Reuse current gesture/window/signature/control assets; minimize dependencies, model loading and runtime processing.

## Browser: text acquisition, local data and audiobook research
Primary destination for OCR/DOM acquisition, local page index, original/ruby/coordinates, figure tagging, unresolved-page management, sentence assembly, pronunciation and saved-first speech. Private browser-extensions, Draft PR #9, extensions/web-ebook-reader. Use normal displayed DOM when permitted; otherwise consider visible-screen OCR only within permission, no circumvention. W0 capability tests first, W1 permitted viewer adapter, W2 independent acquisition/playback pipeline, W3 background/lock/endurance. Browser feasibility remains unconfirmed; do not assert a working replacement or silently revert this role split if W0 fails.
